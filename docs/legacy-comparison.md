# 與舊版比較

舊版以 Streamlit 應用為主；目前版本使用 Open WebUI 聊天，並將羽球資料分析放在獨立服務中。

## 主要差異

| 使用面向 | 舊版 | 目前版本 |
| --- | --- | --- |
| 聊天介面 | 專案自行維護 Streamlit 畫面與對話流程 | 使用 Open WebUI 管理聊天、模型與對話 |
| 資料準備 | 可從介面上傳 CSV 並執行舊版處理流程 | 專案附一份 CSV 與 metadata，也可改用自備 CSV 或 SQLite；目前沒有資料上傳介面 |
| 資料分析 | 在 Streamlit 應用程式內執行模型產生的 Python | Tool Server 將完整唯讀資料快照交給短生命週期 Docker 沙箱分析 |
| 資料探索 | 由舊版應用流程處理資料及上下文 | 摘要與唯讀查詢工具協助模型理解資料；需要分析時仍可讀取完整快照 |
| 圖表 | 以 Matplotlib 圖片在 Streamlit 中呈現 | 驗證後的互動 Plotly 圖表直接顯示於聊天室 |
| 匯出 | 舊版提供包含報告與圖表的封裝流程 | 聊天列表原生選單與評測工作台可直接下載互動 HTML／PDF；評測也保留 JSON 與手動列印頁 |

## 對使用者的影響

目前版本把聊天介面交給 Open WebUI，使用者可在同一對話中接續提問，也可配置模型、Skill 與 Knowledge。資料分析則由 Tool Server 與 Python 沙箱處理。專案附有一份可直接使用的 CSV、metadata 與 100 題評測題庫；若要換用其他資料，需修改本機 `.env`。舊版的 CSV 上傳流程不適用於目前版本。

對一般提問者而言，主要操作仍是用自然語言詢問。模型會依問題查看資料定義，遇到會影響答案且無法合理推定的必要資訊時，可先詢問使用者；需要計算時，則撰寫 Python 對完整資料快照進行分析。

## 目前版本的取捨

- 分離聊天介面與分析服務，減少專案自行維護聊天畫面的工作；代價是 Open WebUI 的模型與工具需要先行設定。
- Python 分析放在短生命週期容器，限制執行時間、資源及網路；Tool Server 仍可存取 Docker daemon，因此目前僅適合可信任的單機開發。
- 互動圖表須符合 Plotly 資料格式並通過伺服器驗證；一般 PNG 不會自動替代未成功附加的圖表。
- 模型可依問題自訂分析程式，但仍需核對資料範圍、欄位定義與統計口徑。流程正常結束不代表答案已證實正確。
