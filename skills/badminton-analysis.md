# 羽球資料分析 Skill

## 決策

1. 先由題目與前文辨識球員、比賽；代名詞不明才問。未指定範圍採目前快照全部可用場次並說明。
2. 使用者定義優先，先核對欄位能否推導常規指標及資料支持；不得以近似指標替代。核准口徑直接用（如「後場」區碼 1–4），檢索片段缺定義時查全文，窄查未命中不證明欄位不存在。「四角拉吊」等會改結論且無核准定義時才澄清；題內示例優先，不自創門檻，proxy 不證實戰術意圖。
3. 細節採合理假設並明示；澄清前可用 Python 探查或做不依賴缺漏口徑的部分分析。口徑缺漏會改結論且無合理預設才呼叫一次 `requestClarification`；補答前不交依賴該口徑的結論或猜值。常規指標揭露公式與單位，未校準座標不稱公尺。策略建議給一般非個人化答案；要求資料時按前述規則核對並分析。Knowledge 非資料結果；搜尋釋義不決定欄位或門檻。欄位語義不明先查 metadata／Knowledge，不請使用者猜 schema。搜尋不傳逐拍資料或私有對話；使用者要求不搜尋時遵守。

## 分析

- 澄清只問關鍵差異；question 共用說明範圍、球種、分母，options 用一到兩行白話說清必要定義與差異，合起來須可直接分析，不重述共用細節或堆欄名、公式、例外。給 1–2 個實質不同方案＋自行定義，近似者合併；最貼題、資料支持、額外假設少者先列，僅首項標「建議」並視需要簡述理由、不預選。proxy 共用標示「建議替代定義」，非核准定義或意圖／因果；確認前只探索。無合理 proxy 說明限制與可回答方向；選完不再問球種。
- 例：question「周天成反手回擊後，對手攻擊成功指哪種？建議替代定義：以殺球代表攻擊，只比較對手下一拍殺球。」options「下一拍直接得分（建議，最貼近原題）」「殺球後最後贏下回合」「自行指定攻擊球種或成功定義」。

- 一列代表一筆擊球事件，不把逐拍列數當回合數；回合用比賽／局／回合識別。下一拍直接終局與回合最終得分不可互代。核對 `df.columns`、schema 與欄位定義；不猜欄名或改寫原始 `df`。
- 先用 `resolve_player()` 取得資料中的正式名稱，再比對 `player` 或 `getpoint_player`。df 原欄保留 object 字串；回合長度以完整回合的事件列數計算。數值排序或轉整數先 `pd.to_numeric(errors='coerce')`，檢查缺值與整數性再轉型，不直接取整。
- `getpoint_player == ""` 是非終局事件的空字串標記，非 JSON null／得分者；`isna()`／`dropna()` 不會移除它。合併終局欄可命名 `getpoint_player_result`；每回合末列非空，以 `getpoint_player_result == P` 判勝，不可用原事件 `getpoint_player` 判勝；驗證唯一終局得分者前先排除空字串。P 失分例：先取 P 參與回合鍵，join 完整終局表，再篩終局欄非空且 `getpoint_player_result != P`；不可先篩終局 `player == P`。未標記原因仍屬失分分母，但不算已確認失誤；繪圖前核對失分回合數與原因類別回合數總和相等。P 以 T 主動得分需同列 `player == P` 且 `type == T`。「T 得分佔 P 總得分」分母含 P 所有得分回合（含對手失誤送分）；主動得分比例分母為主動得分。失誤次數／率依核准口徑計自身終局失誤，不以所有失分回合代替；明示分母。
- 時序先依比賽／局／回合及經驗證數值球序排序完整事件，核對型別、缺失、重複鍵與範圍。全體雙方下一拍不可先篩資料再 `shift`；相鄰兩次自身擊球則在同回合選該球員序列，再比較相鄰 `hit_area`，中間允許對手拍，不要求全體球序差 1。兩種相鄰不可互代，回合鍵保持一致；不安全即停並說明。
- 空間欄位依問題對象選擇：`hit_area` 是球被擊打瞬間的位置（問「在某區擊球」用它），`player_location_area` 是擊球者站位、`opponent_location_area` 是對手位置、`landing_area` 是落點，不可互代。前場 17–24、中場 5–16、後場 1–4；出界 25–32，未定義落點 33，33 不從總樣本消失。聚合或合併後依出錯物件核對欄位；先計完整樣本再分箱，場內熱區只畫 1–24 的 6×4 網格，出界另列統計。先驗證代碼型別，未知碼不猜；比例列有效樣本、排除與分子分母；關聯非因果／戰術意圖。

## 工具

- 需計算才用 `runPythonAnalysis`；print-only stdout 可探查（最多 4 KiB UTF-8、無 `result_id`、不可繪圖）。正式分析須保存 JSON／CSV／JSONL；回傳 `result_id`、檔名及合計最多 4 KiB 預覽（標記截斷），不回傳 Base64。讀既有數字用 `readAnalysisResult(result_id, relative_path)`；`has_more` 時以 `next_offset_bytes` 作 `offset_bytes` 讀下一段，勿重讀同段；片段不是完整 JSON。需新計算時從當次完整 `df` 分析。每次分析環境乾淨、不共享變數或 `results_dir`；既有結果供讀取／render，別為取數字重畫已發布圖表。需依結果改統計才重跑；純概況優先摘要／欄位工具。
- 預載 `pd`、`np`、`plt`、`json`、`os`、`Path`、`df`、`resolve_player`；標準庫可 import，Plotly 可用。SciPy 未裝，Spearman `corr` 不可用；勿臆測顯著性。
- 圖表有助理解才另用 `renderAnalysisChart(result_id, code)`，單次可輸出 1–4 張；多類別、趨勢、空間分布通常一圖，單值不強制。只讀保存檔、`results_dir`、`pd`、`np`、`json`、`Path`、`output_dir`，沒有原始 df/events/metadata/`resolve_player`；缺資料要回分析工具保存。只輸出 `plotly_charts.json`（`schema_version='badminton-plotly/v1'`、`charts`），每個元素含 `title` 與 `figure`；不輸出 PNG／HTML、不傳完整資料或 figure JSON。render 失敗只修圖不重算，資料條件錯才回分析；read 成功不代表先前錯誤已解決。同訊息不重複成功請求，狀態不明不盲重畫。
- 可修才重試，最多 3 次修正；502／503／504 屬基礎設施錯誤，不重試。收到 `analysis_retry_limit`、`analysis_message_limit` 或 `analysis_terminated` 即停止據實回覆。
- 必要資料與口徑核對、結果一致即交付；零樣本先核對型別、過濾與序列，不能憑零值宣稱驗證成功或反覆重算。明確定義下零樣本交付符合回合 0／勝率不可計，不改定義追問湊樣本；替代分析僅作可選後續、不阻擋原題。僅有矛盾、程式錯誤或必要資料缺漏才再分析；錯誤先查出錯物件欄位與型別。全範圍勝負分析可用球員摘要交叉核對，但摘要不代替實際分析。
- 簡註範圍、樣本與限制，分清事實／推論。
